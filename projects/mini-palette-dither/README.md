# mini-palette-dither — 256 色调色板取 32 色子集

`src/palette.py` 保持原样：像素永远按**整张原表**做最近邻映射，输出不变。
新增的 `src/subset.py` 只做一件事：从原表里挑出 `k` 个**已有颜色**（不新增、
不取均值），让整张原表映射的加权平方误差最小。

## 目标函数

对子集 S（原表下标集合）：

```
E(S) = Σ_c  weight[c] · min_{s∈S} dist2(c, s)          dist2 = RGB 平方距离
```

`weight` 是整表映射下的像素直方图（`subset.histogram`）。所以 E 就是"整幅图
每个像素都用最近的选中色表示"时的总平方误差；S 取满整表时 E = 0，映射结果
逐字节与改动前一致（`make test` 里用 `palette.map_nearest` 逐像素比对）。
全部算术是 int64 / Python int，没有浮点累计误差。

## 方法

1. 三个起点（都只读原表、结果确定）：
   - 贪心最大增益（基线 1 本身）
   - 加权中位切分后吸附到表内颜色（基线 2 本身）
   - 加权最远点（仅作第三个起点，不作为对照）
2. 对每个起点做 best-improvement 单交换局部搜索（换出 p、换入 c），
   交换增益对全部候选颜色向量化精确计算；只接受严格改进，因此必然收敛。
3. 取三者中误差最小者，按下标升序返回。

因为两个基线本身就是起点、局部搜索只会降低误差，结果**不会差于两者中的
较好者**（比值 ≤ 1.0），自然满足"≤ 1.05 倍"的要求；稀疏直方图下基线误差
可能本来就为 0，此时同样成立。

**耗时**：搜索预算是固定扫描次数（每个起点 96 次 best-improvement 交换扫描），
不看时钟，因此结果与机器快慢无关；实测各起点一般 1–34 次就收敛。在 256 色表
上 k=32 时为 16–55 ms；k 增大时单次扫描变大，本机 k=200 约 156 ms，仍在
200 ms 内。`make demo` 会打印每次选色的实际耗时。

**确定性**：所有平局按原表下标或固定扫描顺序决定；不依赖 `hash()`、集合
遍历顺序或随机数。`tests/test_subset.py` 会在同一进程内重复调用，并用三个不同的
`PYTHONHASHSEED` 起子进程比对输出。

## 边界行为（有确定结果）

| 输入 | 行为 |
|---|---|
| 原表为空 | `k == 0` 返回 `[]`；`k > 0` 抛 `ValueError` |
| `k == 0` | 返回 `[]`，误差 0 |
| `k < 0` 或非整数 | `ValueError` |
| `k > 原表长度` | `ValueError` |
| `k == 原表长度` | 返回全部下标 `0..n-1` |
| 原表含重复颜色 | 按行区分，返回的仍是互不相同的原表下标；不会重复输出 |
| 权重全 0 / 部分 0 | 合法；相当于这些颜色从不出现 |

## 用法

```python
import subset

palette = [...]                      # 256 个 (r, g, b)
weights = subset.histogram(pixels, palette)   # 整表映射下的直方图
picked  = subset.select_palette(palette, 32, weights)   # 32 个原表下标
report  = subset.compare_methods(palette, 32, weights)  # 与两个基线对照
print(report["ours"]["error"], report["ours"]["colors"])
print(report["greedy"]["error"], report["median-cut"]["error"], report["ratio"])
```

## 与精确最优的差距（补充参考，不属于验收口径）

验收口径是与两个基线中较好者比（≤1.05，实际 ≤1.0）。另用 scipy 的 MILP
（y_s 选色 + x_cs 指派，0 间隙）在 256 色、k=32 的随机直方图上求过全局最优：
本方法 283076034，最优 275526228，比值 1.0274；耗时 58 s 对 50 ms。小表
（20 色取 6）上两者的差距在 0–1.6% 之间，说明局部搜索本身已接近最优。
