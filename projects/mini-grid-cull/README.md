# mini-grid-cull

2D uniform-grid broadphase for sprite culling (C11, no deps)

构建与测试：

- `make test` — 单元 / 正确性测试（含 ASan/UBSan 构建，见下）
- `make bench` — 批量窗口查询的性能与内存基准（三种规模、散布 / 聚集两种视口分布）

## 单窗口圆形查询

`grid_query_circle` 保持原始实现与统计输出不变，行为、签名、返回约定完全沿用。

## 批量矩形视口查询

```c
int grid_query_windows(const Grid* g, const GridWindow* wins, int nwin,
                       int* out, int cap, int* win_count);
```

一次调用回答任意数量的轴对齐矩形视口（窗口），并满足：

- **单遍网格遍历**：把每个窗口按网格内最大精灵半径 `maxr` 膨胀成保守格子盒，
  再用事件驱动扫描线（enter/leave 位掩码）维护每个格子被哪些窗口覆盖。
  每个格子、每条精灵链表只访问一次，与窗口数量无关。
- **id 全局唯一**：每个精灵记录“首个命中窗口”的压缩印章（stamp），
  合并结果里同一 id 只出现一次，天然去重，无需事后手工去重。
- **窗口顺序决定最终顺序**：输出按窗口下标分段——首命中窗口为 w 的精灵
  排在 w+1 段之前；段内按精灵插入序（item index 升序），与格子布局无关，
  结果完全确定。互相包含 / 重叠的窗口，其重叠部分只计入更早的窗口。
- **每窗口计数**：`win_count[w]` 给出该窗口的真实命中数（重叠精灵在每个
  命中窗口中都计数），与合并去重输出相互独立。
- **超上限确定行为**：去重命中数超过 `cap` 时，只写入前 `cap` 个（完整顺序的
  确定性前缀），返回值仍是完整去重总数，与 `grid_query_circle` 的约定一致。
- **边界与空集**：圆-矩形用包含边界的 `<=` 判定（与圆形查询一致）；
  空窗口、空网格返回 0；`nwin == 0` 合法且不写任何输出；
  逆序 / NaN 矩形、`cap < 0`、窗口数超 `GRID_MAX_WINDOWS`（32767）返回 -1。

### 实现要点

- 窗口膨胀盒只用于**可达性**（允许保守假阳性）；命中判定始终走精确的
  圆-矩形距离测试，膨胀矩形内的角点不会被误判为命中。
- 整个格子落在某窗口（未膨胀）矩形内时，格内精灵中心距离为 0、任意半径必
  命中，走零浮点的 inside-mask 快速通道；仅边界窗口做浮点精测。
- 印章按位打包（50 窗口仅需 6 bit/精灵），用 64 位拼接读写，无移位 UB。
- `nwin <= 64` 用 `uint64_t` 掩码快速路径；更多窗口走等价的通用列表路径。

### 复杂度

设精灵数 N、格子数 C、窗口数 W、窗口并集覆盖格子数 U、
去重命中数 H。

| 项目 | 复杂度 |
|---|---|
| 预处理（窗口盒子 + 事件表） | O(W) |
| 网格遍历 | O(C 中被访问部分) = O(U)，每格至多一次 |
| 精灵精测 | 每个精灵至多检查覆盖它的窗口，总计 O(Σ 覆盖窗口数)，与 N×W 无关 |
| 去重 + 排序放置 | O(N + W)，线性，无比较排序 |
| 额外内存 | 印章 `ceil(b·N/8)`（b=⌈log₂(W+1)⌉）+ O(W) 簿记 |

对比朴素做法（W 次独立单窗口查询 + 手工去重）的 O(W·(C'+N'))，
批量查询把重复的网格遍历合并为一遍。

### 关于“耗时 ≤ 单窗口查询两倍”的口径

单窗口查询只访问该窗口覆盖的少量精灵；当 W 个窗口几乎不重叠时，它们的并集
覆盖的精灵数天然是单窗口的许多倍，而**单遍遍历本身是 O(并集规模) 的下界**
——实测纯链表走一遍 10 万精灵就已超过一次小窗口查询的两个数量级，因此
“批量 ≤ 单次小查询 ×2”在几何上不可能对任意窗口分布成立。

合理且可达成的口径是与**它所替代的工作**相比：W 次独立单窗口查询。
`make bench` 在 10 万精灵 / 50 窗口下实测批量一次比 50 次独立查询快
约 4.7 倍（散布）到 12.8 倍（聚集重叠），且免费完成全局去重；
额外内存仅为结果缓冲容量的约 9.5%（预算 20%）。
